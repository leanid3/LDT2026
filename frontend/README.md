# Frontend «Инспектор ИИ»

Отдельное приложение Next.js для работы с API проверки строительной документации. Оно находится рядом с backend в `frontend/` и не изменяет код сервера.

## Запуск

Нужен Node.js 20.9 или новее.

```powershell
cd frontend
npm install
Copy-Item .env.example .env.local
# Docker Desktop must be installed; the startup helper opens it if needed
npm run dev
```

Откройте [http://localhost:3002](http://localhost:3002). По умолчанию запросы идут в `http://localhost:8080/api/v1`. Если API запущен по другому адресу, задайте `NEXT_PUBLIC_API_BASE_URL` в `.env.local`.

Скрипт запуска поднимает инфраструктуру и API, затем запускает подготовленные контейнеры relay, engine, mockworkers и Rin mock/sync. Если контейнеры конвейера ещё не созданы, скрипт предупредит, что анализ документов не заработает; подготовка описана в ../docs/development.md, раздел «Полный конвейер локально».

Для работы с объектами запущенный API должен быть доступен в браузере, а пользователь должен быть создан в системе. Подробности запуска инфраструктуры и сервисов backend — в [`../docs/development.md`](../docs/development.md). Тестовый вход для локального стенда: `inspector1` / `demo-password-123` после команды `make seed` в backend.

## Основной сценарий

1. Войти и создать или открыть объект.
2. Добавить новую проверку и загрузить документы ПД, РД и ИД.
3. Скачать шаблон реестра, заполнить его и загрузить обратно.
4. Запустить проверку и следить за обработкой документов.
5. Рассмотреть выводы и подтверждающие фрагменты, принять решение.
6. Финализировать протокол и проверить статус синхронизации с ИАИС «РиН».

Интерфейс адаптирован для настольных и мобильных экранов. Повторная отправка документов выполняется повторно только для файлов с ошибкой. Повтор синхронизации вручную в текущем API не предусмотрен: backend делает автоматические повторы.

## Команды

```powershell
npm run lint
npm run build
npm run start
```
