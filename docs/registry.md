# Реестр файлов: шаблон и инструкция по заполнению

Реестр — таблица, которая говорит системе, **что за документ каждый загруженный файл**: какая стадия
(ПД / РД / ИД), какой раздел и шифр, какая редакция, утверждена ли она. Без реестра система не знает
стадий и не может ни определить сценарий проверки, ни сравнить документы между собой (ТЗ, «Выбор
актуальной редакции»).

## Где взять шаблон

Шаблон выдаёт сама система — заполнять с нуля не нужно.

| Что | Запрос | Когда использовать |
|---|---|---|
| **Шаблон под вашу проверку** (рекомендуется) | `GET /api/v1/documents/{process_id}/registry-template` | После загрузки файлов. Строки уже содержат `object_id`, `file_name` и `sha256` принятых файлов — остаётся указать стадию, шифр, редакцию, статус. Если реестр уже загружали, в строках подставлены и его значения: можно поправить и загрузить снова |
| Пустой шаблон | `GET /api/v1/documents/registry-template` | Заготовка с заголовками и инструкцией, если файлы ещё не загружены |

Формат — параметр `?format=xlsx` (по умолчанию) или `?format=csv`.

- **XLSX** (рекомендуется): лист **«Реестр»** — заполняемая таблица (для стадии и статуса — выпадающие
  списки, все колонки в текстовом формате, чтобы Excel не превращал `1-12` в дату); лист
  **«Инструкция»** — то же, что ниже: как заполнять, допустимые значения, примеры.
- **CSV**: UTF-8 с BOM и разделителем `;` — открывается двойным щелчком в русской версии Excel.
  Принимаются и `;`, и `,`.

В интерфейсе это кнопки «Скачать шаблон реестра» на шаге загрузки реестра; заполненный файл загружается
туда же (`POST /api/v1/documents/{process_id}/registry`, форматы xlsx / csv / json).

## Как заполнить

Одна строка — один файл. **Заголовки (первую строку) не меняйте.** Колонки `object_id`, `file_name`,
`sha256` в скачанном для проверки шаблоне уже заполнены — не правьте их.

| Колонка | Название | Заполнение | Допустимые значения / формат | Смысл |
|---|---|---|---|---|
| `object_id` | Объект | обязательно | UUID объекта (заполнено) | К какому объекту относится файл |
| `file_name` | Имя файла | обязательно | как при загрузке, с расширением | Сопоставление со строкой. Нужно имя **или** `sha256` |
| `sha256` | Контрольная сумма | обязательно | 64 hex-символа (заполнено) | Главный ключ сопоставления, надёжнее имени |
| `doc_stage` | Стадия | **обязательно** | `PD`, `RD`, `ID` (можно `ПД`, `РД`, `ИД`) | Проектная / рабочая / исполнительная документация |
| `discipline` | Раздел (дисциплина) | желательно | `АР`, `КР`, `ОВ`, `ВК`, `ЭОМ`… | Редакции сравниваются только внутри раздела |
| `document_code` | Шифр документа | желательно | текст, например `АР-001` | У всех редакций одного документа шифр **одинаковый** |
| `revision` | Редакция | желательно | `1`, `2`, `Изм.3` | Номер/обозначение редакции |
| `approval_status` | Статус утверждения | желательно | `DRAFT`, `APPROVED`, `FOR_CONSTRUCTION`, `SUPERSEDED`, `CANCELLED` | см. ниже |
| `approval_date` | Дата утверждения | желательно | `ДД.ММ.ГГГГ` или `ГГГГ-ММ-ДД` | Когда редакция утверждена |
| `sheet_page_range` | Листы / страницы | по необходимости | `1-12` | Какие листы охватывает файл |
| `predecessor_ref` | Предыдущая редакция | по необходимости | имя файла или `sha256` | См. «Несколько редакций» |
| `successor_ref` | Следующая редакция | по необходимости | имя файла или `sha256` | Достаточно указать либо предыдущую, либо следующую |
| `signature_status` | Подпись | по необходимости | `SIGNED` / `UNSIGNED` | На выбор редакции пока не влияет |

«Обязательно» — без этого строка не применяется. «Желательно» — строка принимается, но система
предупредит, что файл не сможет служить эталоном или его редакции нельзя сопоставить.

### Статусы утверждения

| Значение | Русское название (тоже принимается) | Может быть эталоном? |
|---|---|---|
| `APPROVED` | утверждено | да |
| `FOR_CONSTRUCTION` | в производство работ | да |
| `DRAFT` | черновик | нет |
| `SUPERSEDED` | заменено | нет (исключается) |
| `CANCELLED` | аннулировано | нет (исключается) |

### Несколько редакций одного документа

Файлы одного раздела с одинаковым шифром образуют цепочку редакций. Актуальной считается утверждённая
(`APPROVED` / `FOR_CONSTRUCTION`) редакция, после которой нет более новой утверждённой. Чтобы система
поняла порядок, укажите у новой редакции `predecessor_ref` (или у старой `successor_ref`):

| file_name | doc_stage | discipline | document_code | revision | approval_status | approval_date | predecessor_ref |
|---|---|---|---|---|---|---|---|
| АР-001_ред1.pdf | PD | АР | АР-001 | 1 | SUPERSEDED | 10.01.2026 | |
| АР-001_ред2.pdf | PD | АР | АР-001 | 2 | APPROVED | 15.03.2026 | АР-001_ред1.pdf |

Если актуальную редакцию определить нельзя (две утверждённые без связи, цикл ссылок, ссылка на
несуществующий файл), файл получает статус `CLARIFICATION_REQUIRED`: он **не используется как эталон**,
пока реестр не уточнён. Это не ошибка проверки, а честное «данных недостаточно».

## Что ответит система при загрузке

Ответ `POST /documents/{process_id}/registry`:

| Поле | Смысл |
|---|---|
| `total_rows` | Сколько строк с данными в файле (пустые строки не считаются) |
| `matched` | Применено к файлам |
| `unmatched` | Строка корректна, но такого файла среди загруженных нет (имя должно совпадать **точно**, либо укажите `sha256`) |
| `invalid` | Отклонено из-за недопустимых значений — строка не применялась |
| `errors[]` | Причины в виде «строка 3, doc_stage: «проектная» — недопустимая стадия…»; номер строки — как в таблице (1 — заголовок) |
| `warnings[]` | Строка применена, но что-то не заполнено или ссылка не найдена |

Ошибочные строки **не блокируют** остальные. Исправьте таблицу и загрузите её ещё раз — данные
обновятся, повторная загрузка безопасна.

## Частые вопросы

- **Excel «испортил» дату или `1-12`.** В шаблоне колонки текстовые — вводите значения прямо в него.
  Дату принимаем как `15.03.2026`, `2026-03-15`, `15/03/2026`.
- **CSV открылся в одну колонку.** Используйте XLSX или сохраняйте CSV как «CSV UTF-8» — оба
  разделителя (`;` и `,`) распознаются автоматически.
- **Названия колонок по-русски?** Понимаются и они (`Стадия`, `Шифр документа`, `Редакция`,
  `Статус утверждения`, `Дата утверждения`, `Имя файла`…), а также `file_hash` и `sheet/page` из ТЗ;
  надёжнее оставлять заголовки шаблона.
- **Реестр не загружен или пуст.** Загрузили файл без строк — все файлы получают `CLARIFICATION_REQUIRED`
  (причина `REGISTRY_MISSING`). Не загружали совсем — у файлов нет стадии. В обоих случаях проверка
  ничего не сравнит: сначала загрузите реестр.
- **Файл не прошёл проверку** (вирус, повреждён, не тот формат). В шаблон он не попадает — в реестр
  вносятся только принятые файлы.
